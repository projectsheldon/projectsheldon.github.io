Sheldon's Scripting Environment

A Lua 5.4 environment that runs scripts inside the Sheldon overlay with direct access to the game, the renderer, input, files, networking and process memory.

What runs

Scripts run in Lua 5.4, not Luau. The base, math, table and string libraries are available, and Lua 5.4's bitwise operators work without a bit32 library.

Scripts also accept two Luau conveniences: type ascriptions (local part: Part = ... and value :: Type) and compound assignments (+=, -=, *=, /=, %=, ^=, ..=, &=, |=, <<=, >>=). Type ascriptions are ignored at runtime but are used by Auto Complete.

Entry points

game is the DataModel. There is no separate Game or workspace global; use game:GetService("Workspace"), game:GetService("Players") and so on. Instances are wrapped by the Instance type, which exposes their registered and reflected properties, children and methods.

1local Players = game:GetService("Players")
2local Workspace = game:GetService("Workspace")
3local me = Players.LocalPlayer
4​
5print(me.Name, me.DisplayName)
6print(Workspace.Gravity)

Players.LocalPlayer and player character properties are read from the live process. See Instance for property access rules and RBXScriptSignal for events.

Editor

The script editor keeps multiple tabs, runs each tab independently, and exposes Execute, Stop, Restart, Save and Upload. Files can be marked Auto Execute per place or for the current session. The console below the editor receives print, warn and runtime errors.

Auto Complete reads the current game and the Lua environment, so it lists instance children, writable and read-only properties, library functions, services, FFlags, key names and type names as you type.

Auto Complete

      
The editor completes against the live VM and the game's reflection table, not a fixed list of names.

      
Completion is part of the script editor. It inspects the code around the cursor, resolves the expression on the left of a . or : against the running VM, and offers the members that expression actually has. Because instance properties come from the same reflection table the VM reads at runtime, the list includes properties that are not written into this documentation.

tween

      
Interpolate instance properties smoothly over time. Modelled on Roblox's TweenService.

      
FunctionSignatureDescription
tween.Info(time, delayTime?, style?)number, number?, string|int?Builds a TweenInfo table. style defaults to "Linear", delayTime to 0. You can also pass a raw table {time=..., delayTime=..., style=...} anywhere info is expected.
tween.Create(instance, info, props)Instance, table, tableCreates a tween that interpolates each property in props from its current value to the target value. Returns a tween object. The target must still be alive when the tween plays.


      
Tween Object

      
MethodSignatureDescription
tween:Play(waitForFinish?)bool?Starts the tween. When waitForFinish is true, blocks the calling coroutine until every property has finished tweening; otherwise returns immediately. Both tween:Play(...) and tween.Play(...) syntaxes are accepted.
tween:Cancel()Snaps every property back to the value it had when the tween was created. Does not stop already-scheduled ticks – for that, let the tween finish or overwrite the property.


      
Easing Styles

      
Linear, Bounce, Elastic, Exponential, Cubic. Also exposed as tween.EasingStyle.Linear etc. for readability. Pass either the string, the constant, or an integer index (0 = Linear through 4 = Cubic). Unknown styles fall back to Linear.


      
Supported Property Types

      
    
        
  • number – e.g. Transparency, Reflectance, WalkSpeed
    • 
        
  • Vector3 – e.g. Position, Size, LinearVelocity, AngularVelocity
    • 
        
  • Color3 – e.g. Color
    • 
      

      
Common classes such as Part, MeshPart and VehicleSeat are supported directly. Other classes work as long as the game exposes the property.

      
The property must be writable on that instance. Auto Complete lists what is available for the selected instance. Read-only properties, unknown names and unsupported value types raise an error at tween.Create time.


      
Example – Move a part

      

    

    
    
1local part = game:GetService("Workspace").Part
2local info = tween.Info(1.5, 0, "Cubic")
3​
4local t = tween.Create(part, info, {
5    Position = Vector3.new(0, 20, 0),
6    Transparency = 0.5,
7})
8​
9t:Play()

  


      
Example – Wait until finished

      

    

    
    
1local part = game:GetService("Workspace").Part
2​
3local t = tween.Create(part, { time = 2, style = "Bounce" }, {
4    Position = part.Position + Vector3.new(0, 15, 0),
5})
6​
7t:Play(true)
8print("Tween finished – running follow-up code")

  


      
Example – Chained tweens

      

    

    
    
1task.spawn(function()
2    local part = game:GetService("Workspace").Part
3    local up   = tween.Create(part, tween.Info(1, 0, "Cubic"),  { Position = part.Position + Vector3.new(0, 10, 0) })
4    local down = tween.Create(part, tween.Info(1, 0, "Bounce"), { Position = part.Position })
5​
6    up:Play()
7    task.wait(1)
8    down:Play()
9    task.wait(1)
10end)

  


      
Notes

      
    
        
  • Each property tweens independently. Passing multiple properties runs them in parallel on the same schedule.
    • 
        
  • tween:Play(true) waits until every property finishes and pauses all scripts while waiting. task.spawn does not avoid this. Use Play() without the flag and schedule follow-up work with task.delay.
    • 
        
  • Physics-driven properties (Position, CFrame, velocities) update visually, but the engine may resimulate them on the next physics step; combine with anchoring or velocity-zeroing for full control.
    • 
        
  • Tweens continue while the script is yielded.
    • 
      

    

    

      
memory

      
Raw memory read/write operations. Requires the Memory library to be enabled.

      
Requires: Memory library enabled


      
FunctionSignatureDescription
memory.Read(address, type)uintptr, stringReads from memory and converts to the given type. Unknown or write-only types raise an error.
memory.Write(address, value)uintptr, anyWrites a value, choosing the width from its Lua type
memory.Write(address, value, type)uintptr, any, stringWrites a value using an explicit type
memory.GetRTTI(address)uintptrReturns the RTTI class name for an object pointer. If the address is not a vtable pointer, it tries the pointer stored at that address. Returns ??? when neither resolves.
memory.GetBase()Returns the Roblox process base address
memory.Rebase(offset)uintptrReturns base + offset


      
Supported Types

      
Read/Write: float, double, int, uint, bool, byte, short, ushort, int64, uint64, string, vector2, vector3, color3.

      
Write also supports: pointer.

      
Vectors accept a Vector2/Vector3/Color3 value or a table ({x, y, z}, {r, g, b}, or {1, 2, 3}).


      
Write Auto-Decision

      
When the type argument is omitted, memory.Write decides the width from the value:

      
ValueWritten as
integer in int32 range (e.g. 999)int32 (4 bytes)
integer outside int32 rangeint64 (8 bytes)
float (e.g. 0.123)float (4 bytes)
booleanbool
string (e.g. "abc123")null-terminated string
Vector2 or {x, y}2 floats (8 bytes)
Vector3 / Color3 or {x, y, z}3 floats (12 bytes)

      
Pass type explicitly when the field needs a different width (e.g. a double field, a byte flag, or a pointer).


      
Example

      

    

    
    
1local base = memory.GetBase()
2local hp = memory.Read(base + 0x1234, "float")
3print(hex(hp))
4memory.Write(base + 0x1234, 999, "int")

6memory.Write(base + 0x1238, 0.123, "double")
7memory.Write(base + 0x1240, "abc123", "string")

Custom game module

      
Some games parent characters outside Players or use a bone layout the default module cannot read. RegisterGame installs a Lua replacement for the module that finds player roots, reads player data and returns bones. Only one Lua game module can be active; registering another replaces it.

      

        
Manual run only: RegisterGame refuses to run from auto-execute or session auto-load, and it also refuses when the current place id is not in placeIds. Execute it from the editor.

      

      
FunctionSignatureDescription
RegisterGame(definition)tableRegisters the module, adds a tab named after name, and makes it the active player provider.
UnregisterGame()Removes the module if the calling script owns it. The default module returns.

      
Definition

      
KeyTypeDescription
namestringRequired. Tab name and module name.
placeIdstableRequired. Place ids this module accepts. Numbers or numeric strings.
getParentsfunctionOptional. Returns a table of Instances that contain the player models. Returning nothing falls back to Players.
getPlayerfunctionOptional. Called with a parent Instance; returns a table with Character/model, userId, username/Name, displayName/DisplayName, Team/teamName, Humanoid, rigType and bones.
getBonesfunctionOptional. Called as getBones(character, rigType); returns a table of bone name to Instance. Names such as Head, HumanoidRootPart, UpperTorso, LeftUpperArm and RightFoot are read.
onUpdatefunctionOptional. Runs once per module update. Errors are reported to the console.

      
Example

Garbage Collector

      
Read and write values in the game's Lua objects. getgc lists objects or finds a key; rawget and rawset work on one object address; setgc writes a key.

      
FunctionSignatureDescription
getgc(includeAll?)bool?Returns an array of GC object addresses. The default returns tables only; true also includes strings, functions, userdata and threads. Use type(address) to identify each entry.
getgc(key)stringScans the GC for the first table that has key and returns its value. Primitive values are decoded to Lua values; tables, functions and userdata come back as their address. Returns nil when no table has the key. The string form and the boolean form cannot be combined.
setgc(key, value)string, bool | number | addressFinds the first table with key and overwrites it. Accepts bool, number, or a GC address for object values. Strings are rejected – pass an existing TString address instead. It does not create keys, does not write a GC barrier, and silently does nothing if no table has the key.
rawget(addr, key | true)number, string | boolReads a field on the external table at addr. Pass a string key for one field, or true to dump the whole table as a Lua table. Missing keys return nil. GC-typed values come back as address numbers; call rawget on those addresses to go deeper.
rawset(addr, key, value)number, string, anyWrites an existing field on the external table at addr. Accepts nil, bool, number, or an address for object values. Returns true on success and false if the key does not exist. It does not create keys or write a GC barrier.


      
Example

      

    

    
    
1-- Walk every table once. This is the only form that visits all of them.
2for _, t in next, cheat.getgc() do
3    if type(t) == "table"
4       and cheat.rawget(t, "MaxAmmo") ~= nil then
5        cheat.rawset(t, "MaxAmmo",     math.huge)
6        cheat.rawset(t, "CurrentAmmo", math.huge)
7    end
8end
9​
10-- Key lookup returns the first match only, not every table.
11local ammo = cheat.getgc("MaxAmmo")
12if ammo then print("first MaxAmmo seen =", ammo) end
13​
14-- setgc also writes the first table that has the key.
15cheat.setgc("MaxAmmo",     math.huge)
16cheat.setgc("CurrentAmmo", math.huge)
17​
18-- Dump every field on a table (debugging).
19local dump = cheat.rawget(someAddr, true)
20for k, v in pairs(dump) do print(k, "=", v) end

RBXScriptSignal (Events)

      
Roblox-style connections backed by the VM scheduler.

      

    

    
    
1local connection = signal:Connect(function(...)
2    print(...)
3end)
4​
5connection:Disconnect()  -- removes only this callback
6connection:Stop()        -- stops the script slot that owns the callback
7​
8-- Inside a coroutine: yields until the next fire and returns its arguments.
9task.spawn(function()
10    local a, b = signal:Wait()
11end)

  

      
Connect returns a connection table. Wait raises Cannot call Wait on the main thread - use task.spawn when called from the script body, because it needs a coroutine to suspend.

      
Callbacks run on the VM worker thread. They can yield. An error inside a callback is caught and does not disconnect the other callbacks.

Notes

      
Additional implementation details and behavior notes.

      
    
        
  • The VM runs Lua 5.4, not Luau. Only base, math, table and string are opened. There is no coroutine, os, io, utf8, bit32 or debug library exposed to scripts.
    • 
        
  • Luau type ascriptions (local x: Type, value :: Type) are removed before compilation. Compound assignments +=, -=, *=, /=, %=, **=, ..=, &=, |=, <<= and >>= are expanded. continue, generalized iteration and Luau-only syntax are not supported.
    • 
        
  • pcall and xpcall are replaced so a stopped script can interrupt protected calls. The VM also checks its stop flag from a Lua instruction hook every 10 instructions.
    • 
        
  • Scripts run on a worker thread. task.wait and RBXScriptSignal:Wait need a coroutine and raise on the main script body. WaitForChild blocks the calling thread instead of yielding.
    • 
        
  • print() writes with a [print] prefix and warn() with [warn]. Runtime errors go to the console as [error].
    • 
        
  • tick() returns GetTickCount64(), milliseconds since system start, not UNIX time.
    • 
        
  • loadstring also strips type ascriptions. It returns (function, nil) or (nil, error_message).
    • 
        
  • Instance reads check built-ins, signals, the class property map, the game's reflected properties, then direct children. Writes go through the class map and reflected properties. Read-only writes raise an error; they do not fail silently.
    • 
        
  • Instance:IsA compares the exact ClassName; base classes do not match. Parent is read-only in this build.
    • 
        
  • game is the only DataModel global. There is no Game or workspace global; use game:GetService("Workspace").
    • 
        
  • string.regex uses C++ std::regex with ECMAScript syntax, so it expects \d+, not Lua's %d+.
    • 
        
  • File, HTTP response, HTTP request-body, base64, hash and compress inputs are capped at 10 MB. File listings stop at 256 entries.
    • 
        
  • HTTP requires https:// unless Require HTTPS is turned off in the Lua VM settings. Timeouts are 1-15000 ms, default 5000.
    • 
        
  • compress.Compress does not store the original size, but compress.Decompress expects a 4-byte header. The two functions do not round-trip in this build.
    • 
        
  • Remote spy members and FireServer / InvokeServer are not exposed to Lua. Remote instances use the standard Instance API.
    • 
        
  • The old Class Properties page is deprecated. The live property list comes from Auto Complete and the game's reflection table.
    •
